## 一、定位

在旧版「仔仔鼠AI直播助手」之上新增一个**可开关的智能体大脑**，让直播间的回复从「规则 + 话术库」升级为「智能体自主判断」，同时把产品视觉从蓝紫改为青绿、正式更名。

一句话概括改动：

> 加一个智能体页面和一个总开关。开关关掉，产品行为与旧版一字不差；开关打开，弹幕/礼物/关注/口播全部交给智能体自己判断怎么回。

### 1.1 三个硬性前提

1. **不覆盖旧版**。旧版代码、配置、存档、发布包原封不动躺在归档目录里，随时可跑、可回溯、可继续维护。
2. **音色继续用 MiniMax**。不引入 GPT-SoVITS 或任何本地 TTS 引擎，`hub/tts.py`、`hub/minimax_client.py`、`hub/voiceworkshop.py` 的合成与克隆逻辑零改动。
3. **话术管理、音色工坊两个页面照旧保留**。智能体不是替代它们，而是在它们之上多加一层。

### 1.2 与早期论证文档的关系

`智能体方案文档.md`（2026-09-11）与 `仔仔鼠智能体版方案.md`（2026-09-20，已随旧版归档）主张的是**另一条路线**：GPT-SoVITS 替换 MiniMax + 智能体中心替换话术管理。

**该路线已作废**，本文档为准。两者的差异逐条对照如下：

| 议题 | 已作废路线 | 本设计 |
|---|---|---|
| TTS 引擎 | GPT-SoVITS 本地 sidecar（127.0.0.1:9880） | **MiniMax 保持不变** |
| 音色工坊 | 重写为本地参考音频库，移除 Key 与槽位 | **保持原样**，Key/15 槽/7 天保活全留 |
| 话术管理 | 被「智能体中心」替换 | **保留**，作为智能体的素材库与检索源 |
| 智能体入口 | 占用话术管理页 | **独立新增第 5 个页面** |
| 生效方式 | 默认生效 | **系统配置里的总开关**，默认关闭 |
| 护栏 | 全部保留，AI 在护栏内自主 | **除敏感词双检外全放开**（见 §六） |
| 视觉 | 蓝白不变 | **蓝紫 → 青绿**（见 §十二） |
| 发布包 | exe + GPT-SoVITS 整合包 + 启动脚本 | **exe + 现有发布包形态不变** |

## 四、架构总览

### 4.1 开关 OFF（等同旧版）

```
事件源 ──→ Router（聚合/连击/冷却/概率）──→ 队列(P0>P1>P2, 过期丢弃, P2让位)
        ──→ ScriptRuntime 三级应答 ──→ Generator ──→ Safety ──→ MiniMax ──→ VB-Cable
```

与旧版 `main.py` 装配完全一致，**代码路径不做任何分支**——即 OFF 不是"另写一套"，而是"不启用新模块"。

### 4.2 开关 ON（智能体接管）

```
事件源 ──→ Router【降级为事件旁路 + 输入侧敏感词闸门】
        ──→ AgentBrain（每事件一次决策）
              ├── 单场记忆（最近事件 / 最近说过的话 / 临时笔记）
              ├── 检索层（L1 素材直注 + L2 关键词召回，预留 L3）
              ├── LLM（复用 config.llm）→ AgentDecision
              └── 决策日志落盘
        ──→ 队列（仅保留优先级排序，无过期丢弃、无让位）
        ──→ Safety 输出侧双检 ──→ MiniMax 流式 ──→ VB-Cable
```

关键点：**接管点只有一个——应答决策**。上游（采集/事件）、下游（队列/安全/合成/播放/热键/看门狗）全部复用旧版代码。

## 五、接管机制设计

### 5.1 Router 在 agent 模式下的降级规则

`hub/router.py` 的 `Router` 新增构造参数 `mode`（`"rules"` 默认 / `"agent"`），并支持热切换 `set_mode()`。

agent 模式下各处理器的行为：

| 处理器 | rules 模式 | agent 模式 |
|---|---|---|
| `_handle_chat` | 敏感词闸门 → 无意义弹幕按 20% 概率丢 → 进聚合窗口 | 敏感词闸门 → **直接产出单条事件上下文**（不聚合、不丢） |
| `_handle_gift` | 连击状态机，5 秒超时结算 | **每条礼物事件独立产出**，连击合并交给智能体判断 |
| `_handle_follow` / `_handle_fansclub` | 30 秒冷却 + 概率门槛 | **每条都产出**，是否感谢、怎么感谢交智能体 |
| `_handle_enter` | 受 `event_enabled` 开关控制 | 同左（用户级开关，非限流） |

保留在 Router 侧的只有两件事：
1. **输入侧敏感词闸门**（`SafetyFilter.check_input`）——违禁弹幕连智能体都不给。
2. **F9 暂停**（`_paused`）——用户主动控制，不属于限流。

### 5.2 队列在 agent 模式下的行为

`PrioritySpeakQueue` 新增 `no_expire` 标志：

| 行为 | rules 模式 | agent 模式 |
|---|---|---|
| `_is_stale` 出队年龄检查 | 礼物 30s / 弹幕 90s / 口播 180s，超时丢弃 | **永远返回 False**（不丢弃） |
| `put_idle` P2 让位 | 任一层有积压则放弃本轮 | **不检查积压，直接入队** |
| 优先级排序 P0>P1>P2 | 固定 | **保留**（数据结构本身，非限流） |
| `interrupt` 头插 | 仅中/高档礼物 | **由智能体决策里的 `interrupt` 字段决定** |
| `pause()` 清空积压 | 是 | **保留**（用户主动暂停语义） |

> 优先级与头插保留的原因：它们决定**播放顺序**，不是"少说几句"。若去掉，任务将无法排序播放。
> 暂停清空保留的原因：这是用户按 F9 的主动意图，不是系统限流。

### 5.3 智能体决策契约

AgentBrain 每收到一个事件，调用 LLM 一次，要求返回结构化 JSON：

```json
{
  "should_reply": true,
  "priority": 1,
  "interrupt": false,
  "tone": "热情",
  "emotion": "happy",
  "speed": 1.05,
  "reason": "新观众提问游戏玩法，属于值得回的有效弹幕",
  "reply_text": "兄弟这个游戏就是点点小手柄下载，进去挂着就行，很休闲的",
  "memory_note": "刚有个新观众问怎么下载，已经答过了"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `should_reply` | bool | **自主判断要不要回**。false 则本次不产出任务 |
| `priority` | 0/1/2 | 建议优先级：0=礼物级插队，1=互动回复，2=闲时口播 |
| `interrupt` | bool | 是否插到队列头部立刻说（仅 priority=0 时生效） |
| `tone` | str | 本轮语气（写进决策日志，供"决策透视"展示） |
| `emotion` | str | 情绪档位，取值见 §8.6。空则回落 `default` |
| `speed` | float | 语速，0.5~2.0，缺省 1.0 |
| `reason` | str | **一句话说明为什么这么回**，决策透视页展示，可回看智能体的思考 |
| `reply_text` | str | 要说的文本；空串视为不回 |
| `memory_note` | str | 可选，写入单场临时笔记 |

**容错链**（`decide.py`）：

1. JSON 解析失败 → 尝试提取首个 `{...}` 块重解析
2. 仍失败 → 降级为「纯文本当作 `reply_text`，`priority=1`，`reason="解析降级"`」
3. LLM 调用异常 → 复用旧版兜底：`safety.fallback_reply`（受 `fallback_enabled` 控制），与旧版行为一致
4. 无 LLM 配置（`llm.api_key` 为空）→ 智能体页显示灰色提示，开关无法开启，表单与旧版链路照常可用

设计原则：**永不静默**（除未配置 LLM 与 `should_reply=false` 的主动不回）。

### 6.1 知情决策声明

**本次不加任何限流，包括队列节流。** 这是经过两轮确认的显式决策，其可预见的后果如下，需一并接受：

| 后果 | 机理 | 观测手段 |
|---|---|---|
| LLM 调用量随弹幕量线性增长 | 每个事件一次 LLM 调用，弹幕风暴下 QPS 等于弹幕 QPS | 决策日志条数、`stats` 面板 |
| Token 成本上升 | 每条事件都带 system prompt（人设 + 素材 + 记忆） | 决策日志内的 token 计数（若接口返回） |
| 延迟上涨 | 并发 LLM 请求无上限，随弹幕量增长 | 决策日志内的 `latency_ms` |
| 队列无界增长 | 不再丢弃过期任务，队列只增不减（除非播放追上） | `queue.qstat()` 的 total |
| 可能重复致谢 | 冷却与概率取消后，连续关注/礼物逐条触发 | 决策日志回看 |

设计文档记录此决策为**已知风险**（§十六），并保证：**观测手段齐备**（决策日志 + 状态面板），后续若需加限流，只需在 §六 表格里把对应项从"放开"改回"保留"——因为 `rules` 模式的代码全部原样保留，开关一关就回来了。

### 7.1 页面结构

**① 对话调参**（标签：对话调参）

| 用户说 | 智能体动作 | 落盘位置 |

技术实现：
- LLM function calling，把可改字段注册成工具集（人设 / 节奏 / 口播 / 话术池 / 知识库）
- 写回走现有 `hub/config.py` 的行级替换（保注释）与 `scriptstore.save_profile`（护栏保留）

- 一键「送入智能体」→ 显示完整决策（`should_reply` / `priority` / `tone` / `reason` / `reply_text`）
- 可选「用当前直播音色试听」→ 调 MiniMax 合成并播放

**③ 反馈进化**（标签：反馈进化）

- 直播中枢的消息流里，每条 AI 回复旁挂三个**图标按钮**（内联 SVG，无 emoji）：

## 八、音色与情绪设计

### 8.1 两条分界

音色与情绪在本设计里被明确切成两件事处理：

| 维度 | 本次处置 | 理由 |
|---|---|---|
| 音色 `voice_id` | **不变**。仍由存档 `current_voice` 决定整场直播的音色，不按句切换 | 按句切音色需反复重建 `TTSClient`，代价高、收益低（观众感知的是情绪而非音色个体） |
| 情绪 / 语速 / 音调 | **动态化**。由智能体每轮决策输出，逐条覆盖 | 这是"有感情"的实际来源，MiniMax 原生支持 |

### 8.2 情绪档位（Emotion Profile）

MiniMax 情绪枚举固定 8 个：`happy` / `sad` / `angry` / `fearful` / `disgusted` / `surprised` / `calm` / `fluent`；另有 `speed`（0.5~2.0）、`vol`、`pitch`（-12~+12）。

- 每个存档维护一组**情绪档位集合**，出厂默认 `happy` + `calm`
- 档位在**话术管理页**勾选（从 8 个枚举里选），并可按档位批量生成音频
- 特殊档 `default` 永远存在、不可删除，承载旧版的扁平音频与音色档案参数
- 实际预生成份数 = `1（default） + 勾选档位数`

### 8.3 播放分派（三级）

给定一条任务（文本 + 情绪 `e`），按顺序尝试：

| 顺序 | 条件 | 行为 | 延迟 |
|---|---|---|---|
| 1 | `audios[voice][e]` 存在且 `text_hash` 匹配 | 播预录音频 | 0 |
| 2 | `e` **已在档位集合内**但该条缺音频 / hash 失配 | 回落到 `audios[voice]["default"]` | 0 |
| 3 | `e` **不在档位集合内**（智能体选了未预生成的情绪） | **现场 TTS 合成，带上该情绪** | 2~4 秒 |

第 2 步与第 3 步的区别是要点：**已登记的档位缺音频时保守回落到 default（不额外花钱、不额外等待）；未登记的档位则现场合成（保留表现力自由度）**。这是本设计对"预生成"与"表现力"的折中。

### 8.4 存档结构升级 v4

```jsonc
// v3（旧）
"audios": {
  "voiceA01": {"file": "a1b2.wav", "text_hash": "9f3c…"}
}

// v4（新）
"audios": {
  "voiceA01": {
    "default": {"file": "a1b2.wav", "text_hash": "9f3c…"},
    "happy":   {"file": "c3d4.wav", "text_hash": "9f3c…"},
    "calm":    {"file": "e5f6.wav", "text_hash": "9f3c…"}
  }
}
```

迁移规则（`scriptstore` 启动时自动执行）：

1. 读到 `audios[vid]` 含 `file` 字段 → 包成 `{"default": <原值>}`，`version` 置 `4`
2. 迁移**幂等**：重复启动不会二次包装
3. 其余档位**按需补生成**：在话术管理页点「补生成」批量补齐缺失档位
4. `text_hash` 语义不变，逐档位各自记录；文本改了该音色的**所有档位一起标 stale**

### 8.5 情绪与文本的耦合

- **同一文本 × 不同情绪 = 不同音频文件**。MiniMax 合成时情绪会改变韵律与停顿，无法从一份音频派生，必须各合成一份
- 因此「改文本」会作废该条**全部情绪档**的音频，符合直觉
- 文本中的 `|` 停顿标记（每竖线 0.4 秒）在预生成时按档位各自解释，无需特殊处理

### 8.6 智能体侧约束

`brain.py` 组 prompt 时必须把**当前存档的情绪档位集合**列给 LLM：

```
可用情绪档位：default, happy, calm
（选 default 或上述档位可立即出声；选其他情绪将现场合成，延迟约 2~4 秒）
```

决策契约中 `emotion` 字段的校验规则（`emotion.py`）：

| 输入 | 处置 | 日志事件 |
|---|---|---|
| 在档位集合内 | 直接用 | — |
| 在 8 枚举内但不在集合内 | 接受，走现场 TTS | `emotion_onsite` |
| 不在 8 枚举内 / 空 / 非法 | 回落 `default` | `emotion_invalid` |
| `agent.emotion.enabled = false` | 一律 `default` | — |

### 8.7 音频体积控制

按 24 kHz 单声道 WAV、每条 8~10 秒约 400 KB、MiniMax 每条合成 1~2 秒估算：

| 档位数 | 30 条话术的文件数 | 磁盘 | 首次批量合成 |
|---|---|---|---|
| 1（仅 default） | 30 | 约 12 MB | 约 1 分钟 |
| 2（出厂默认） | 60 | 约 24 MB | 约 2 分钟 |
| 3 | 90 | 约 36 MB | 约 3 分钟 |
| 4 | 120 | 约 48 MB | 约 4 分钟 |

预估公式：`磁盘 ≈ 话术条数 × 档位数 × 0.4 MB`。话术池超过 200 条时建议档位数不超过 3。

## 九、检索层设计

智能体的检索源 = **话术存档 + 反馈示例库**，共用一个 `retriever` 接口。

### 9.1 三层与本次实现范围

| 层 | 机制 | 本次 | 说明 |
|---|---|---|---|
| **L1 素材直注** | 人设/游戏知识/风格参数 + 话题话风参考 + 最多 N 条样本示例，全量拼进 system prompt | 实现 | 素材 < 50 条时效果与 RAG 无实质差异，零延迟零成本 |
| **L2 关键词粗筛** | 复用 `_keyword_match` 的字符 2-gram Jaccard 相似度，召回 top-K | 实现 | 毫秒级、零依赖；复用 `RECENT_PICK_WINDOW_S=600` 做去重 |
| **L3 语义向量 RAG** | 切块 → embedding → 向量索引 → 语义召回 | **不做，仅预留接口** | 触发条件：素材条目 > 100 条，或 L2 召回命中率实测偏低 |

### 9.2 接口契约（为 L3 预留）

```python
class Retriever:
    """检索层统一接口。L2 与未来的 L3 都实现它。"""

    def index(self, profile: dict, examples: list) -> None:
        """重建索引（存档切换/编辑/反馈回流后调用）。L2 为无操作。"""

    def retrieve(self, query: str, top_k: int = 5) -> list[dict]:
        """返回 [{"id","kind","match","reply","score","has_audio"}]。

        kind: "sample" | "topic" | "example"（反馈回流样本）
        has_audio: 该条目是否有当前直播音色的有效音频（复用 _resolve_audio 语义）
        """
```

`brain.py` 只依赖这个接口。将来换 L3 只需替换实现类，`brain.py` 零改动。

### 9.3 两条硬约束

1. **音频不进检索**。检索的是文本知识；音频是「用什么声音说」的载体。但检索结果必须按 `has_audio` 过滤/标注——复用旧版 `_resolve_audio` 的
   `stale` 语义（文本 hash 失配视为无音频）。
2. **音色走存档 `current_voice`**。智能体模式下发声链路与旧版一致：有当前音色音频可播预录音频，无音频则现场 TTS 念文本。这保证开关 ON 不会让直播间换一个人说话。

## 十、记忆设计

### 10.1 单场内存（不做跨场次持久化）

`hub/agent/memory.py` 维护一个进程内环形缓冲，**进程重启即清空**：

| 缓冲 | 内容 | 默认容量 | 用途 |
|---|---|---|---|
| `events` | 最近收到的 `LiveEvent` 摘要（类型/用户/内容/时间戳） | 50 | 判断连击、判断是否重复提问、感知直播间氛围 |
| `spoken` | 智能体最近说过的回复文本 | 20 | **防复读**——避免反复说同一句话 |
| `notes` | 智能体自己写入的临时笔记（`memory_note` 字段） | 10 | 记住本场的临时上下文，如"刚答过下载问题" |

> **容量是上下文窗口，不是限流。** 环形缓冲的容量决定喂给 LLM 的上下文长度（token 成本与判断质量的平衡），不限制"回复多少条"。这与本次"不加限流"的决策不冲突。

### 10.2 持久化的只有两样

| 落盘物 | 路径 | 说明 |
|---|---|---|
| 反馈样本库 | `profiles/<pid>/agent/examples.jsonl` | 好评/改写样本，跨场次累积 |
| 反馈原始记录 | `profiles/<pid>/agent/feedback.jsonl` | 含否定的原因标签 |

其余一律不落盘。**隐私考量**：观众昵称与弹幕内容不会被长期留存（除非主播主动采纳为样本）。

## 十二、配置变更

### 12.1 新增 `agent` 段

```yaml
agent:
  enabled: false              # 总开关：true = 智能体接管直播；false = 完全等同旧版
  retrieve:
    layer: l2                 # l1 = 只做素材直注；l2 = 追加关键词召回；l3 预留
    top_k: 5                  # L2 召回条数
  memory:
    max_events: 50            # 单场事件记忆容量（上下文窗口，非限流）
    max_spoken: 20            # 已说过的回复记忆容量（防复读）
    max_notes: 10             # 临时笔记容量
  feedback:
    enabled: true             # 是否在直播中枢显示反馈按钮
  emotion:
    enabled: true             # 情绪动态化总开关（false = 所有回复一律 default 档）
    onsite_fallback: true     # 未登记档位是否允许现场 TTS（false = 回落 default 预录音频）
  decision_log: true          # 是否落盘决策日志
```

> `emotion.profile`（情绪档位集合，如 `["happy","calm"]`）**不写在 config.yaml**，而是存在存档内（`profiles/<pid>/profile.yaml` 的 `emotions` 字段）——因为档位与音频文件一一绑定，跟着存档走才不会错位。

### 12.2 `tts` 段（仅新增情绪覆盖语义）

```yaml
tts:
  voice_id: "demoVoice001"    # 存档 current_voice 优先，此处仅启动兜底
  model: "speech-2.8-hd"
  speed: 1.0
  vol: 1.0
  pitch: 0
  emotion: ""                 # 仅作全局兜底；智能体模式下由逐条覆盖取代
```

**字段无增删**，语义微调：`emotion` 从"全局固定值"变为"缺省兜底值"，智能体模式下每条任务携带自己的 emotion 覆盖它。

MiniMax 的 Key 与 endpoint 仍存 `voice_clone/voice_clone_data/config.json`，仍由音色工坊页维护。

### 13.2 语义色：填充档 与 文字档（必须成对使用）

| 语义 | 填充档（底） | 文字档 | 文字档对比度 | 浅底上（`*-soft`） |
|---|---|---|---|---|
| 成功 | `--green #0fa968` / `--green-soft #e5f7ee` | `--green-text #0b7a48` | 白底 5.40:1 | 4.85:1 |
| 错误 | `--red #e5484d` / `--red-soft #fdecec` | `--red-text #c0392b` | 白底 5.44:1 | 4.76:1 |
| 警示 | `--gold #f5a623` / `--gold-soft #fdf3df` | `--gold-text #8f6206` | 白底 5.36:1 | 4.87:1 |

### 13.3 不用 emoji：SVG mask 图标库

前端**不出现任何 emoji**。做法不是「换成另一个字符」，而是**内联 SVG data-URI + CSS `mask` + `background: currentColor`** —— 图标自动跟随元素文字色（`.ok` 绿 / `.err` 红 / `.warn` 棕），且不依赖系统 emoji 字体。

`:root` 内置 5 个图标变量：

| 变量 | 图形 | 替换的原字符 | 位置 |
|---|---|---|---|
| `--ico-check` | 对勾 | `✓` ×6 | 密钥格式校验、保存结果、测试历史、测试结果大图标 |
| `--ico-cross` | 叉 | `✗` ×6 | 同上（失败态） |
| `--ico-warn` | 三角警示 | `⚠` ×1 | 音色保活剩余天数（`.vw-keepalive.warn`） |
| `--ico-tip` | 灯泡 | `💡` ×1 | LLM 连通性测试建议（`.llm-test-advice`） |
| `--ico-arrow` | 右尖角 | 无（新组件） | `.pipe-hint` 步骤胶囊分隔符 |

用法约定：

```css
.st-mark::before {
  content: ""; display: inline-block; width: 13px; height: 13px;
  background: currentColor;                       /* 跟随元素文字色 */
  -webkit-mask: var(--ico-check) center/13px 13px no-repeat;
          mask: var(--ico-check) center/13px 13px no-repeat;
}
```

- 页面内联 SVG（如链路阶段图标）用 `stroke` + `currentColor`，不引外部图标库，保持单 HTML 文件、零网络依赖。
- `data:` URI 里的 `#` 必须写成 `%23`，否则整条 URI 被截断。
- 例外：`<option>` 无法承载 SVG，模型下拉的「手动输入模型名…」直接去字符，语义由选项文本表达。
- `→`（U+2192）属正常排版标点，不是 emoji，正文与注释中保留；但**可见 UI 文案**里那一处已升级为 `.pipe-hint` 真组件。

`.pipe-hint` 组件：原本 `<span class="hint">弹幕 → 回应 → 合成 → 输出</span>` 与下方 `.pipe` 视觉链路重复，现改为「浅绿胶囊 + 灰色 SVG 尖角」的步骤条，成为可复用微组件。

### 13.4 对比度策略（品牌色的固有取舍，须知情）

实测（WCAG 2.1 公式，脚本化，非目视）：**26 项关键组合全部达标**。

必须知情的两点：

1. **`#00C29A` 承载白字的上限是 2.29:1。** 这是色相本身的约束 —— 要达正文 AA 4.5:1 需压到 ≈`#008065` 的墨绿，会背离「参考 WorkBuddy 颜色」的要求。实测 WorkBuddy 自身设计系统（`--wb-brand-primary` = `--wb-palette-brand-8`）同样把该色直接当按钮底色与品牌文字色用，也不满足 AA。**本版保留品牌色相**，把白字载体压到图形/大字 3:1 门槛（新增 `--brand-solid`），需要严格 AA 时改用 `--brand-deep`（7.45:1）。

2. **令牌选型规则**（照做即可达标）：

| 你要做的 | 用哪个令牌 | 实测 |
|---|---|---|
| 实心按钮 + 白字 | `--brand-solid → --brand-press` 渐变 | 3.02–3.92:1（图形/大字标准） |
| 实心按钮 + 白字，且要正文 AA | `--brand-deep` 纯色 | 7.45:1 |
| 品牌色当**文字** | `--brand-deep` | 7.10:1 |
| 品牌色当**图标/描边** | `--brand-press` | 3.92:1 |
| 品牌色当**浅底/装饰/辉光** | `--brand-primary` | — |
| 成功/错误/警示**文字** | `--*-text` | 4.76–5.44:1 |
| 成功/错误/警示**填充** | `--green` / `--red` / `--gold` | — |

## 十六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **无限流 → LLM 成本与延迟失控** | 弹幕风暴下 token 消耗与延迟随弹幕量线性增长 | 已知情决策（§6.1）。观测齐备：决策日志含 latency、状态面板显示本场决策数。`rules` 模式代码全部保留，改回只需把 §六 对应项从"放开"改"保留" |
| **队列无界增长** | 弹幕量长期大于播放速度时队列只增不减 | 决策透视页显示队列长度；F9 暂停可一键清空；后续可按需给 P2 让位加回 |
| **可能重复致谢** | 冷却与概率取消后连续关注/礼物逐条触发 | 智能体靠单场记忆自主判断（`spoken` 缓冲防复读）；决策日志可回查 |
| **每事件一次 LLM 调用成本高** | 一条弹幕一次完整 prompt（人设 + 素材 + 记忆） | L1 素材直注的示例条数可调；后续若成本过高，可考虑批量决策（一次调用处理窗口内多条事件） |
| **LLM 输出 JSON 不合规** | 决策解析失败 | 三级容错链（§5.3）：提取 JSON → 纯文本降级 → 兜底口播 |
| **智能体语气漂移** | 越说越不像主播 | L1 人设直注 + few-shot 示例 + 反馈进化闭环；决策透视可见每轮语气标注 |
| **多情绪音频库膨胀** | `磁盘 ≈ 条数 × 档数 × 0.4 MB`；档位数失控会显著占用空间与合成时间 | 档位数在页面显式勾选（默认 2 档）；话术池超 200 条时建议不超过 3 档；补生成按需触发而非自动全量 |
| **未登记情绪的现场合成延迟** | 智能体选了没预生成的档位 → 该条回复延迟升至 2~4 秒 | 这是保留表现力自由度的显式代价；若实测影响观感，把 `agent.emotion.onsite_fallback` 置 `false` 即回落 `default` 预录音频 |
| **情绪档位与存档错位** | 换存档后音频档位不匹配 | 档位集合随存档存储（非 config.yaml），换存档即随之切换；`selector` 三级回落兜底 |
| **一致性风险：预录音频情绪滞后** | 文本改了但只补生成部分档位，出现新旧文本混播 | `text_hash` 逐档位校验，失配即视为无音频并回落，不会播出旧文本 |
| **新旧版配置/存档互污** | 误改归档内容 | 版本隔离原则（§3.3）：新版本不读写归档目录任何文件 |
| **绿色主题改不彻底** | 残留蓝紫元素 | 前端颜色全部走 CSS 变量，改一处即全局生效；改造后逐页目视核对 |
| **归档后旧版跑不起来** | 误以为归档损坏 | 已排除 `.venv`/`dist`/`build`（§3.2）；重建 venv 一条命令；路径已验证全相对 |

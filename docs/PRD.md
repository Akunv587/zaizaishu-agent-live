## 一、背景与目标

### 1.1 背景

旧版「仔仔鼠AI直播助手」是一个可用的抖音直播 AI 互动工具：采集弹幕/礼物/关注 → LLM 生成口语回复 → MiniMax TTS → VB-Cable 虚拟声卡 → 直播伴侣麦克风播出。它的回复决策是**规则驱动**的：关键词直出 → LLM 从样本库选一条 → 现场生成，配合一套硬编码的护栏（聚合窗口、连击、冷却、概率、队列过期）。

规则驱动的结果是**可预测但机械**：无意义弹幕一律按 20% 概率丢、关注感谢一律 30 秒冷却、口播一律从话术池轮换、语气千人一面。

### 1.2 目标

在**不破坏旧版可用性**的前提下，新增一个可开关的智能体，让回复决策从「规则」升级为「自主判断」，并把产品视觉与品牌更新为青绿主题与新名称。

### 1.3 三条不可妥协的前提

| # | 前提 | 含义 |
|---|---|---|
| P1 | **不覆盖旧版** | 旧版全部内容原样归档，两版各自独立 git 仓库，互不影响 |
| P2 | **音色继续 MiniMax** | 不引入 GPT-SoVITS 或任何本地 TTS 引擎 |
| P3 | **话术管理、音色工坊保留** | 智能体不是替代它们，而是在其之上加一层 |

### 1.4 成功判据

1. 开关关闭时，产品行为与旧版**逐项一致**（回归测试全绿 + 关键场景人工比对无差异）
2. 开关打开时，同一场重放弹幕的回复**明显更像真人主播**（语气有变化、无意义弹幕不再机械丢、口播不再照稿念）
3. 情绪档位开启后，直播间**能听出同一音色的不同情绪**
4. 主播能在页面上看到智能体**每一条回复的判断依据**

## 二、用户与场景

### 2.1 用户

**单主播**（产品名中的"仔仔鼠"）。非技术人员，用桌面应用双击启动，通过浏览器控制台配置。硬件为普通游戏本（RTX 3050 Laptop 4G 级别），直播时同机运行游戏 + OBS + 直播伴侣。

### 2.2 核心场景

| # | 场景 | 期望结果 |
|---|---|---|
| S1 | 首次开播 | 双击 exe → 首跑种子存档自动落地 → 无需配置即可开播（沿用旧版体验） |
| S2 | 日常开播（不开智能体） | 与旧版完全一致 |
| S3 | 日常开播（开智能体） | 弹幕被挑着回、语气跟着内容变、口播像现场说的 |
| S4 | 调教人设 | 在智能体页用自然语言说"说话随意点"，配置热生效，可撤销 |
| S5 | 试玩验证 | 开播前在试玩区造几条弹幕，看智能体怎么回，不改动直播状态 |
| S6 | 反馈进化 | 直播中给好回复点"采纳"，坏回复点"弃用"并选原因，越用越像自己 |
| S7 | 情绪控制 | 感谢大额礼物时声音明显更激动 |

### FR-4 智能体页面

新增第 5 个标签页「智能体」，含四个功能区。

#### FR-4.1 状态条

顶部常驻状态条：接管状态（色点 + 文字）、当前模型名、本场决策条数、平均决策耗时。点击状态色点跳转到系统配置开关。

#### FR-4.2 对话调参

| 项 | 说明 |
|---|---|
| 布局 | 左侧对话面板 + 右侧当前配置实时预览 |
| 能力 | 自然语言改配置：人设风格、口播节奏、话术池增删、游戏知识库、回复字数上限 |
| 回显 | 每次改动明确显示「改了哪个字段、旧值 → 新值」 |
| 撤销 | 保留最近 20 次改动快照，一键撤销 |
| 降级 | 无 LLM Key 时面板置灰提示，表单照常可用 |

**验收标准**

- AC-4.2.1 说"口播太频繁了"→ 口播间隔参数变化且热生效，回显旧值→新值
- AC-4.2.2 说"加一条话术：小手柄点一下支持主播"→ 话术池新增该条
- AC-4.2.3 撤销后配置回到改动前状态，且 `config.yaml` 注释未丢失
- AC-4.2.4 无 LLM Key 时面板置灰，话术管理页表单功能不受影响

#### FR-4.3 试玩调试

| 项 | 说明 |
|---|---|
| 能力 | 手工构造事件（类型/用户/内容/礼物名与价值），送入智能体看决策 |
| 展示 | 完整决策：是否回、优先级、语气、判断依据、回复文本、所用情绪 |
| 试听 | 可选「用当前直播音色试听」，调 MiniMax 合成播放 |
| 批量 | 支持一次投递多条，模拟弹幕风暴，观察判断倾向 |
| 隔离 | **不写入单场记忆、不进队列、不影响直播** |

**验收标准**

- AC-4.3.1 构造一条弹幕可获得完整决策展示
- AC-4.3.2 试玩期间直播链路行为不受影响（记忆与队列无变化）
- AC-4.3.3 试听按钮能出声（MiniMax 已配置时）

#### FR-4.4 反馈进化

| 项 | 说明 |
|---|---|
| 入口 | 直播中枢消息流每条 AI 回复旁的三个图标按钮 |
| 操作 | 采纳（对勾图标）/ 弃用（叉图标，可选原因标签）/ 改写（铅笔图标，弹出输入框） |
| 回流 | 采纳与改写版本写入 `profiles/<pid>/agent/examples.jsonl` |
| 注入 | 生成时从示例库召回好评样本作 few-shot |
| 统计 | 页面展示样本总数、本周新增、采纳率、各原因标签分布 |

**验收标准**

- AC-4.4.1 点采纳后示例库文件新增一条，字段完整
- AC-4.4.2 点弃用可选原因标签（不像主播 / 太长 / 跑题 / 重复）
- AC-4.4.3 改写后新版本入库，原回复不参与 few-shot
- AC-4.4.4 示例库有样本后，同场景回复语气可见变化

#### FR-4.5 决策透视

| 项 | 说明 |
|---|---|
| 内容 | 时间倒序列表：事件 → 是否回 → 优先级 → 耗时 → 判断依据 → 回复 → 语气 → 情绪 → 素材引用 |
| 数据源 | `logs/agent-YYYYMMDD.jsonl`（最近 500 条） |
| 聚合卡 | 本场决策数 / 平均延迟 / 不回比例 / 各类事件占比 |

**验收标准**

- AC-4.5.1 每条决策都能看到「为什么这么回」
- AC-4.5.2 能看到素材引用（如果引用了某条样本）
- AC-4.5.3 聚合卡数值与日志实际条数一致

### FR-5 智能体接管直播

| 项 | 说明 |
|---|---|
| 需求 | 开关 ON 时，弹幕/礼物/关注/粉丝团/进场/定时口播全部由智能体自主判断并生成回复 |
| 接管点 | 仅"应答决策"一处；采集、队列、安全、合成、播放、热键、看门狗全部复用旧版 |
| 自主范围 | 判断哪些弹幕值得回 / 自主选语气 / 口播内容现场生成 |
| 护栏策略 | **除敏感词双检外全部放开**（详见 `DESIGN.md` §六） |
| 容错 | 永不静默（除未配置 LLM 与主动判断不回）；解析失败三级降级 |
| 降级 | LLM 异常时使用旧版兜底口播文案 |

**验收标准**

- AC-5.1 同一场重放弹幕，ON 与 OFF 行为可对比出差异
- AC-5.2 无意义弹幕由智能体判断（不再受 20% 概率参数约束）
- AC-5.3 礼物/关注不再受冷却与概率约束，但智能体靠记忆避免重复致谢
- AC-5.4 敏感词弹幕仍被输入侧拦截（不进智能体）
- AC-5.5 智能体生成的回复仍被输出侧敏感词检查
- AC-5.6 LLM 返回非法 JSON 时不静默、不崩溃，走兜底
- AC-5.7 未配置 LLM 时开关不可开启，产品不崩

### FR-6 情绪档位与多情绪音频

| 项 | 说明 |
|---|---|
| 需求 | 音色固定不变，情绪成为可控维度，且预录音频提供多情绪版本 |
| 音色 | 全场固定走存档 `current_voice`，不按句切换 |
| 档位集合 | 每存档一组，出厂默认 `happy` + `calm`，在话术管理页勾选（MiniMax 8 个枚举内） |
| 特殊档 | `default` 永远存在、不可删除，承载旧版音频与音色档案参数 |
| 存档结构 | 升级 v4：`audios[voice_id][情绪档] = {file, text_hash}` |
| 旧存档 | v3 自动迁移（扁平结构识别为 `default` 档），幂等 |
| 补生成 | 其余档位按需批量补生成（页面按钮触发） |
| 播放分派 | ①命中档位音频 → 播预录 ②档位内缺音频 → 回落 default ③未登记档位 → 现场 TTS 带该情绪 |
| 智能体约束 | prompt 中列出可用档位；返回未登记情绪时允许现场合成 |

**验收标准**

- AC-6.1 旧 v3 存档拷入后能自动迁移并可正常直播
- AC-6.2 迁移是幂等的（重复启动不二次包装、不重复生成）
- AC-6.3 勾选 `happy` 后点补生成，音频目录出现对应档位文件，`text_hash` 正确
- AC-6.4 智能体回"感谢大哥"时播的是 `happy` 档音频（与非 happy 档可听出差异）
- AC-6.5 智能体返回未登记情绪时现场合成成功，延迟在 2~4 秒
- AC-6.6 改一条话术文本后，该条**所有**情绪档音频被标 stale，不播旧文本
- AC-6.7 音色全场不切换（日志中 `voice_id` 恒定）

### FR-7 检索层

| 项 | 说明 |
|---|---|
| 检索源 | 话术存档（人设/知识/样本/话题）+ 反馈示例库 |
| L1 | 素材直注：人设 + 游戏知识 + 风格参数 + 话题话风参考 + 最多 N 条样本示例 |
| L2 | 关键词粗筛：字符 2-gram Jaccard 召回 top-K（复用旧版相似度），带最近使用去重 |
| L3 | **本次不实现**，但必须预留接口（`retrieve(query, top_k)`） |
| 约束 | 音频不进检索；检索结果标注 `has_audio`（当前音色是否有有效音频） |

**验收标准**

- AC-7.1 L1 素材全部出现在 system prompt 中（人设、游戏、话题参考、样本示例）
- AC-7.2 L2 能召回语义相近的关键词（复用旧版 0.6 阈值可调）
- AC-7.3 替换 retriever 实现类时 `brain.py` 无需改动（接口隔离验证）
- AC-7.4 素材超 50 条时 prompt 长度不失控（示例条数有上限）

| NFR-7 | 可降级 | 任一智能体子功能失败均不影响旧版链路可用 |
| NFR-8 | 无网络依赖的前端 | 前端单 HTML 文件，图标内联，不引外部 CDN |
| NFR-9 | 成本可见 | 决策日志记录每次调用的耗时与（若接口返回）token 数 |

## 五、优先级与里程碑

| 优先级 | 内容 | 说明 |

## 六、范围外（明确不做）

- GPT-SoVITS 或任何本地 TTS 引擎
- 移除或重写话术管理、音色工坊
- 音色"性格标签"体系（不做标签，表现力只由情绪参数承担）
- 按句切换音色（`voice_id` 全场固定）
- 从一份音频派生多情绪（必须各合成一份）
- 本地微调训练 / 声音克隆模型自训
- L3 语义向量 RAG（预留接口）
- 跨场次长期记忆持久化
- 任何形式的限流、节流、频控
- 直播状态检测、多账号、多游戏轮播
- 前端 emoji
- 企业交付（离线授权 / 代码混淆 / 激活服务器）
